## HIGH: real defects, reproduced

**H1. The scoreboard snapshot is unauthenticated authority.** `_write_snapshot`
deliberately writes `index/scoreboard.json` without a lock, and `_load_snapshot`
trusts it after checking only the schema version. Anyone who can write the
bucket prefix can set a future `through_day` with fabricated totals and the UI
will display them, with no Object Lock trail, while the ledger short-circuits.
The ledger is tamper-evident; its cache is not, and the cache wins.

**H2. Readiness can report ready while reads are failing.** `/readyz` does one
listing plus `library.scan()`. On a cache hit `scan()` returns early, so
`last_scan_unreadable` stays empty from the last good scan and the probe returns
200 for the whole cache window even as every GET fails. That is the exact shape
of the Class B outage, which is what the probe was added to catch.

**H3. Cross-instance staleness can cause a duplicate paid generation.** The
projection cache is per process and `invalidate()` only clears the local one.
An instance that generated an asset does not tell any other instance, so for up
to 120 seconds a second instance can answer the same prompt from a library
that does not contain it yet, and pay to generate it again. That is the one
outcome the product exists to prevent.
